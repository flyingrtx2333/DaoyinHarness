# Background account checks and account menu

Window focus and visibility changes previously called the full connection flow, clearing the active transcript and draft and showing “正在连接工作台” even when the account was unchanged. These events now coalesce into one background identity check. A matching account only refreshes profile/expiry; it does not reload sessions, reset a running turn, move focus or replace draft edits. Changed accounts and revoked access still clear the previous private view. Initial entry and explicit retry retain their visible connection states.

The sidebar avatar opens a compact menu with personal profile, settings and sign-out. The profile link opens the existing platform `/my/profile` page in a new tab. Settings control the actual send shortcut and automatic reply scrolling, with browser-local preference persistence and recoverable storage errors. Logout uses the existing authenticated account revocation endpoint, then removes the platform's legacy browser token by its known storage key without reading it, clears private UI state and returns to the visitor workbench. Failed logout leaves the current page available for retry.

Design: a compact workbench popover, shared typography/spacing/colors, upward-opening menu and a native settings dialog. Menu arrows/Home/End/Escape, outside click, focus return, modal keyboard behavior and 44px mobile controls are implemented. Mobile navigation gains an accessible close control so the open sidebar cannot cover its only exit.

Evidence: Windows typecheck/lint/build and automated state tests; Edge mocked-API checks at 320/390/1280/1920px include a slow background check while continuing to type, focus-event coalescing, no transcript reload, long-session expiry, account switching/revocation, persisted settings and failed/successful logout. Browser screenshots use fixture accounts. Production deployment evidence is added after activation. No real-model quality, screen-reader conformance or Core Web Vitals claim is made by these checks.

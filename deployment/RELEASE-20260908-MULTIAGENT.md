## 已接通的能力

`delegate_agent` 创建独立子会话和子 Run；`delegate_parallel` 支持最多三个输入任务、最多两路并发；`workflow_run_inline` 支持最多五步，字符串步骤顺序执行，显式节点可声明前向无环依赖并在依赖完成后汇总。父子关系和子轨迹由数据库持久化，普通会话列表不混入子会话。

子 Agent 复用 AgentEngine，只获得同一授权下的只读业务工具，不具备递归委派或长期记忆写入工具。父子共享模型调用与工具调用上限，保留父 Agent 最后一次汇总调用额度，每轮最多八个子 Run。结果交接只传递有来源 Run ID 的可见结果，不收集或传递隐藏推理。取消和失败停止后续调度；不会自动重放结果不确定的模型/工具请求。诊断 API 返回父子关系、状态和有界结果。设计详见 [ADR-0020](../docs/adr/0020-cloud-child-orchestration.md)。

## 未隐藏的失败与当前限制

1. 首次部署暴露主平台网关仍拒绝新工具。首次真实请求失败后立即恢复旧版，再补齐可信工具描述符与严格参数校验。失败记录为 `20260908-delegate.json`；网关修复后的实际委派记录另存，未覆盖失败样本。
2. 随机验证码逐字符反转的交接任务两次在第二个子模型请求超时；第一步结果已正确持久化到第二步输入。记录为 `20260908-handoff-parallel.json` 中 handoff 和 `20260908-handoff-repeat.json`。后端计时分别达到 136306/173247 毫秒，超过 Harness 单次模型 90 秒的边界。此类任务的模型稳定性仍未通过，不能将五类基础能力的通过解释为所有任务稳定。
3. 后续一批业务交接的两个子步骤已完成，但父汇总及下一条任务被原登录授权的累计 60/60 次额度阻断；记录为 `20260908-final-business-cancel.json`。调用数包含此前历史；没有修改或清空历史额度。之后的一次性测试授权只用于独立验收。
4. 取消证明的是 Harness 不再派发后续工作，且父子任务均进入终态；不证明已经提交给供应商的推理立即停止或一定不计费。失败/取消请求的完整 token 和最终成本可能不可得。
5. 本次没有浏览器登录流程验收、负载测试、跨租户对抗性模型测试、召回率真值评测，也没有实现跨实例持久调度、崩溃自动续跑、并行写业务、多层递归团队或独立可视化拓扑编辑器。

因此这是已上线、具备真实执行证据的受控云端多 Agent 版本，而不是无条件的全面稳定性验收。验收期间共保留十一条实际尝试记录：六条通过、五条未通过；未通过包含一次修复前网关策略拒绝、两次随机码模型超时、两次累计额度阻断。不能将这一小批结果外推为普遍成功率。

# 插件页概念与文案预算

用户同时指定 concept-to-ui 与 frontend-design，因此结合前者的概念选择流程和后者的产品工作区设计准则。当前只生成可评审方案，未改产品代码。

目标是选择可用插件并了解尚未接入的能力。截图机器测量 1375×870，为侧栏之外的插件内容区；沿用 52px 顶栏、1120px 目录最大宽度、20px 页面 padding，保留上一轮 A 版侧栏和相邻会话页面。

视觉主张：以用途和可用状态组织目录，减少重复说明，保持全站紧凑尺度。共享正文14px、导航13px、辅助12px、标题16px、控件36px、卡片padding16px、圆角8/12px。生成图尺寸偏差不得成为新全站样式。

## 文案处理

- 删除“选择可用插件，在会话中使用”引导句。
- 删除大段能力标签的可见堆叠；搜索仍可匹配已有能力元数据。
- 待接入项仅保留一处明确状态；删除“已有...能力，尚未接入此工作台”和“暂不可选”重复说明。
- 官网知识用途为“检索道引产品与方案的公开资料”，保留公开资料范围。操作简化为“使用”，仍走已有会话插件选择，不引入安装、授权或执行能力。
- 短剧制作：“从剧本到视频成片”；网站与应用：“对话创建网站与轻应用”；文旅影像：“生成景区场景人像”。这三项仍待接入，没有操作按钮。

## 方案

A：四行平面列表，以图标/名称用途/状态操作三列对齐。
B：可用一项作为紧凑横条，待接入三项共用明确分组，避免重复标签。
C：两列两行紧凑卡片，名称用途与图标并排，操作收进同一区域，去掉所有标签和底栏。

状态契约：保留已有搜索无结果、执行中禁用、已选插件、授权失效与重连；状态不可仅用颜色表达。选择后验证窄屏、键盘、200%文字放大、长文案、正常与空搜索；移动操作至少44px。素材均为现有PluginIcon、DOM、CSS，无需装饰位图。无新后端功能或生产操作。

## 生成后检查

三版均已逐图检查：完整视口、四个真实插件、搜索、唯一可用入口与明确待接入状态均可见；无冗余标签或第二套状态说明，构图分别为列表、状态分组、两列紧凑卡片。推荐 C，既保留辨识度也减少阅读与占用高度；A 适合更纯粹的工具目录，B 更突出当前可用项。

生成器实际输出均为1576×998，区别于要求的1375×870；图标和文字存在概念放大，最终必须映射回全站tokens，不能直接照抄图中尺寸。概念文字可读不等于通过浏览器可访问性、字体放大或响应式验收；这些检查在用户选择后实现阶段执行。所有位图仅为设计证据，不会作为产品页面背景。

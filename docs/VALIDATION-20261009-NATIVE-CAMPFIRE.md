环境为独立 Linux 生产服务器、Node 22.23.2、普通道引账号登录后的 `https://harness.daoyintech.com` 工作台。公开 UI revision、全部发布文件哈希及 runtime 就绪状态均已核对；普通账号 `/runtime` 返回上述 Agent revision。主平台在实际运行镜像的基础上只替换三个已提交文件，并设置 `AGENT_YINGHUO_ENABLED=0`。未迁移用户数据，未重启或改动原营火服务。UI 发布未重启 Agent。

最初资源服务配置检查失败并自动恢复；加入启动就绪等待后发布成功。首次图片分块被旧 `/api/v1/cloud/` 的 64 KiB 代理限制拦截，普通账号得到 `CLOUD_REQUEST_UNCERTAIN`。只给 `/api/v1/cloud/resources/control` 增加 512 KiB 的专用入口，保留其他云端入口的 64 KiB 限制；配置校验后重新验证上传成功。未完成上传的资源继续保留历史，但不进入素材选择。

工具的最终动作均完成。诊断中后两个场景的 `model_inclusive.failures` 分别为 1 和 2，最终 run 为 completed；小样本不能当作模型全程无重试或稳定性保证。模型最后将 `hasAudio=true` 描述为“平台自动生成音轨”；本次实现实际是给无音轨图片片段补静音音轨，没有音乐、配音或 AI 音频。`hasAudio` 只表示音轨存在，不等于有可听音乐或语音。

另用同一真实账号及已上传素材验证资源保护行为：

- 将参考视频作为计划片段，实际返回 `CAMPFIRE_REFERENCE_NOT_FOOTAGE`，没有保存该违规计划。
- 保存带“缺少门头实拍”的计划后请求 render，实际返回 `CAMPFIRE_MISSING_SHOTS`；查询持久化状态只包含计划事实，没有开始剪辑。
- 重复已完成计划的 render，返回原输出 ID 和 `reused=true`，没有覆盖或新建成片。

四个 run 的已计价用量记录合计 **1.10334000 CNY**。辅助调用存在 `UNCONFIGURED` / `MISSING_USAGE` 记录，未计入这个数；它不是所有调用的完整结算费用或账号总扣费。各次输入、工具事件、诊断、上传文件哈希、实际保护响应和逐条用量记录保存在本次工作区忽略的 `.cache/campfire-live/` 中。

Safari 已登录真实云端，检查桌面约 1324 px 和窄窗口约 574 px：素材库、店铺选择、文档上传、聊天“＋ → 营火能力”、已有参考视频选择、选择状态、聊天恢复后的成片预览按钮及实际 MP4 播放。通过文件选择器上传仓库的 `docs/CAMPFIRE.md` 后，真实素材库出现该文档。长参考文件名不会挤掉已选营火名称。没有使用模拟 API 的浏览器验证；没有声称完成 390 px 手机或真实移动设备验收。

Mac Node 22.23.2 的相关 TypeScript / ESLint、Python AST 和 `git diff --check` 通过；服务器从精确 Git 对象完成 runtime、资源服务和 UI 打包。它们是静态或打包检查，不是模型行为测试，也不是 Windows 验收。

## 仍然明确保留的边界

当前版本没有 AI 补镜头、配音、音乐生成或付费视频生成。缺镜头会询问，且不自动执行这些操作。门店摄影素材的效果、有可听语音或音乐的多片段拼接、跨账号隔离和大量素材分页没有在本轮真实样本中验收。实际店铺宣传片质量需要用户的真实店铺资料与实拍素材再验证。

旧 Story 资产接口仍因业务表不可用而加载失败；页面提供独立的可读提示，内置营火素材上传、查询和成片不依赖该接口。本轮未修改那个业务数据库。

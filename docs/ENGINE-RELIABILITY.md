## 推理与工具循环

`AgentEngine` 先验证完整模型回复和整个工具批次，再允许第一项工具执行。工具调用 ID 必须唯一，参数必须为有界 JSON；同批次结构错误或超过剩余次数预算时，整批拒绝，不先执行一半。模型超时或取消后不自动再请求一次，也不接受迟到回复触发新工具。

回合内使用规范化参数和结果指纹判断重复。仅改变调用 ID、对象字段顺序或结果摘要措辞，不算进展。默认情况下，没有其他写操作介入时，不重复同一个写操作；未知结果和可重试错误也不能单凭模型判断重做。可信工具定义可声明 `repeatable: true`，用于确实允许连续重复的操作，但仍受权限、次数及无进展门禁约束。这个标记不能由模型参数指定。该机制不是跨回合幂等服务，不能代替业务账本。

相同只读请求默认允许三次相同结果；状态变化会重新计数。反复被无进展门禁阻止后，保留最后一次模型调用用于不带工具的总结，并记录失败原因。它只识别精确参数/结果重复，不宣称可以判断任意语义上的进展。所有总结仍在原 `maxSteps` 内，不额外突破调用预算。

同一引擎内同一会话不能并行执行；存储层与云端租约负责跨引擎的运行边界。相同回合已经终结时直接返回记录，不再调用模型；回合已经开始但结果不完整时拒绝盲重放。在新回合继续前，需要把旧回合恢复为明确的中断状态。

## 上下文

自定义系统提示词仍保留会话摘要、执行证据、中断警告和回合指令。业务 Profile 改变助手行为，但不再无意删掉已压缩历史的唯一上下文入口。

上下文预算保留当前用户目标和最近完整工具请求/结果组。较早工具组转为带调用编号和省略说明的检查点，历史按完整回合裁剪；最新工具输出必要时用合法 JSON 预览缩小。用户当前目标、执行参数和安全指令不被静默剪掉，无法容纳时明确报错。字符预算是序列化体积门禁，不是模型 tokenizer 的精确 Token 数。

压缩摘要改为 `deterministic-trajectory-v2` 的有界 JSON，包含来源事件范围和省略回合数。只覆盖连续完整的已结束回合，不跨越未结束或交错执行的回合。旧摘要仍可作为明确标记的历史参考，不改写旧事件。工具关联键包含会话、回合和调用编号；只有 started 没有结果的操作标记为 outcome_unknown，不能当作已成功或可安全重试。

| 选项 | 默认值 | 作用 |
| --- | --- | --- |
| `maxContextCharacters` | 96,000 | messages、工具 schema 与系统提示 metadata 的合计字符上限 |
| `maxContextMessages` | 36 | 避免长会话超出网关消息数量限制 |
| `maxUnchangedToolResults` | 3 | 相同请求连续得到相同结果的次数 |
| `modelTimeoutMs` | 90,000 | 单次模型等待时限，无自动重试 |
| `maxSteps` / `maxToolCalls` | 16 / 32 | 内核默认；官网仍显式使用 12 / 24 |

## 云端单实例恢复

新增 `cloud_runtime_lease` SQLite 表。打开数据库本身不取得租约；标准 `main.ts` 在配置校验后取得 30 秒租约，每 10 秒续约，再提供服务。有效租约存在时第二个实例启动失败；租约丢失时停止新请求及模型/工具工作，数据库事务拒绝旧实例的迟到写入。

获得租约后，标准入口把遗留 running Run 追加为 interrupted，保留其请求、已完成工具证据和事件顺序；不恢复模型循环，不重发外部操作。同一个 requestId 仍返回原来的中断任务。只有在新回合中核对原操作状态后，才能决定下一步。

首次从没有租约的旧版本升级，必须先停止旧 systemd 服务并确认进程退出；旧二进制不认识新租约表，不能与新版本重叠运行。之后的相同数据库单实例交接由租约检查约束。不要通过删除数据库或租约行来强行启动。正常关闭先停止任务，再释放自己的租约；崩溃连接不会立即释放，后继实例需要等待过期。

这不是跨机器分布式调度，也不能撤销已经提交给外部供应商的操作或保证不计费。若外部任务结果未知，只能查询原任务或人工核对，不能以服务重启为理由重复付费提交。

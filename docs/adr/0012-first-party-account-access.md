# ADR-0012：所有业务插件自动继承同账号完整权限

日期：2026-09-06。状态：完整权限规则已接受；赛事读取免二次授权已部署并验证生产登录入口，详见 [上线记录](../../deployment/RELEASE-20260906-ACCOUNT-ACCESS.md)。真实账号业务试用待用户完成。其他插件及写入能力按本规则接入，尚未交付。

## 决策

所有 Harness 业务插件默认自动继承当前登录账号在所选个人或企业空间内已有的完整业务权限，包括读取、创建、修改、删除、生成、导出、发布和管理等该账号本来可执行的操作。此规则适用于赛事、短剧、网站、文旅、同账号跨应用数据与记忆，以及以后接入的其他业务插件，不限于只读功能。

登录后即可使用已接入能力，不要求用户逐插件授权、安装后再次同意、勾选权限范围、签发凭证或粘贴令牌。不得另设 Agent 专用角色、缩减的权限副本或人工资源白名单。插件接入时复用业务权限解析和已有账号连接，内部凭据自动签发、续期并随业务权限变动失效。

“完整权限”指当前账号本身的全部业务权限，不产生跨账号、跨企业或超出订阅权益的访问。既有业务交易规则、用量计费和审计继续适用，不得额外叠加插件授权关卡；需要用户明确交易内容的业务交互应复用原有流程，不能要求用户重复确认已明确发出的操作。

主平台从已验证的登录会话派生账号、当前空间、应用和业务资源范围。执行身份可以继续使用服务端短期凭据，但其签发与续期属于内部实现，不是用户操作。浏览器、模型和请求正文均不能自行指定另一个账号。业务成员关系失效、退出登录或账号切换后，旧身份不能继续执行业务操作。

## 赛事首个接入

赛事工作台通过同源 bootstrap 使用当前登录账号进入，无独立授权表单。未登录时显示平台登录入口；已登录但无相应业务访问权时明确显示无访问权限，不回退为公开访客身份。已有八项只读工具、输入检查、结果过滤和执行前资源校验继续生效。当前账号能在赛事业务中读取的数据，应能直接通过 Harness 查询，不额外要求 `saishi.agent.read` 或人工赛事白名单。

平台内部必须复用业务实际的账号与资源权限规则，不根据前端提交的 userId、tenantId、eventId 或“同账号”声明扩大读取范围。账号/空间标识稳定用于会话隔离，内部凭据刷新不应创建新的用户空间。请求回执必须随账号隔离，不能在切换账号后重发前一账号的请求。

## 与既有决策的关系

替代 [赛事插件](../SAISHI-PLUGIN.md) 中第一方工作台手动签发和粘贴授权的产品流程，并取代其他规划中逐插件或同账号跨应用二次授权的要求。保留 [共享云端基础](0006-shared-engine-cloud-foundation.md) 中可信执行身份、每步访问校验和用量归属的要求。

道引业务通过 MCP 接入 Harness 时同样遵循自动继承规则，协议选择不构成手动授权的例外。外部 MCP 客户端连接道引服务的现有凭据接口仍保留，不能把该流程搬进 Harness。接入外部服务时复用已有有效账号连接及其可用权限；外部服务尚未建立连接或其自身要求重新登录时，需要完成该服务必要的身份连接，Harness 不再增加自己的逐插件授权步骤，也不声称可以绕过外部服务的权限限制。

当前实现仍是赛事八项读取工具的自动账号访问；删除、覆盖、发布和付费生成尚需实现相应业务工具，短剧、网站和文旅也尚未接通。此实现进度不构成未来只读权限限制，后续能力上线即使用账号已有权限，不再要求补充插件授权。本轮不迁移历史数据。长期记忆的候选确认与来源追踪属于记忆内容生命周期，不应被误用为阻拦同账号跨应用数据访问的插件授权。

## 验收

验证已登录账号无需手动凭据即可进入、未登录只能登录、同账号已有业务范围直接可读、跨账号和企业资源仍拒绝、退出/切换账号后清空旧视图与隔离请求回执、撤销业务访问权后立即拒绝，以及官网访客流程不受影响。模拟 HTTP 与浏览器验证不等于真实平台联调或线上部署。

每个后续插件还须验证：账号已有的读写、生成与管理能力无需额外授权即可调用；权限变动自动生效；没有 Agent 专用权限子集；切换账号后不能继续执行旧账号操作。未实现的能力明确标为待接入，不能展示为待用户授权。

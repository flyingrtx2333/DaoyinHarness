# ADR-0032：营火复用既有登录建立服务端账号连接

日期：2026-10-09。状态：旧桥已实现并部署；用户随后选择 Harness 内置能力，本决策由 [ADR-0034](0034-native-campfire-media-workflow.md) 取代。真实账号样本在工具授权阶段被拒绝，未证明业务查询成功。

## 决策

营火已有独立手机号账号与 Streamable HTTP MCP。道引平台账号 ID 和营火 UUID 不相同；主平台 `users.user_phone` 可由用户更新，因此不能以手机号相等作为跨服务资源授权依据，也不将个人 MCP 凭证搬进 Harness。

营火页面在服务端功能启用后，使用现有 HttpOnly 营火登录和道引共享账号 Cookie 自动调用同源 POST `/api/harness/connect`。营火服务将道引 Cookie 仅通过受保护的服务端请求交给主平台解析，主平台验证有效账号及当前空间成员关系。营火使用已验证的两个账号建立连接，不接受浏览器提供的 userId、tenantId 或手机号，不覆盖已经指向其他营火账号的连接。没有营火登录时仅完成营火自身必要的登录，不添加 Harness 插件授权、范围勾选或手动令牌步骤。

连接保存在营火账号库的 `yh_harness_accounts`，按道引账号、道引空间和营火实例隔离。它是账号关联，不存放密码、Cookie 或可执行凭证。同一个营火账号只关联同一个道引账号，可用于该账号的多个空间；账号行锁保护首次并发关联，切换道引账号不能自动继承前一个账号的营火连接。资源仍属于原营火账号，不迁移客户数据。新增表由显式发布步骤应用，进程启动不自动创建。

工具执行继续使用现有平台执行身份：Harness → 主平台 `/api/internal/agent-apps/v1/` → 营火 MCP → 原营火 API。主平台与营火之间使用独立服务密钥；营火在每次 MCP 请求及内部 API 请求时回查主平台授权，并验证营火成员关系、账号连接和店铺。不能用主平台服务密钥单独指定任意营火 UUID。服务密钥和 Cookie 不进入浏览器返回、模型、工具结果或会话记录。

本轮接入既有 14 项 MCP 能力，包括读、写、制作与导出，按 ADR-0012 继承关联账号已有权限。原预算、requestKey、草稿 revision、排队取消和人工审核规则继续生效；不自动重试未知结果，不替用户审核或向短视频平台发布。HTTP API 的账号操作排队执行，网页和 Harness 使用同一队列，防止跨会话读写观察半完成操作。后台制作生命周期仍由原营火业务负责。

统一工作台与独立云端项目／资源账号可装配营火工具，不要求为营火购买不相关的赛事或 Story 权限。没有启用营火时原目录和会话身份保持兼容；安装边界不随工具目录变化。界面只依据账号 bootstrap 实际返回的营火工具显示已启用，不能以静态目录冒充业务可用。

## 验证边界

本轮已进行了 macOS 静态检查与独立 Linux / Node 22.23.2 的 Harness 局部类型检查。真实账号关联、实际 MCP 执行、真实模型与持久化、桌面／窄屏交互、Windows 验证未进行；独立 Linux / Node 22 发布检查与健康／资源完整性检查已完成。发布组件、配置及小样本验收见 [营火接入](../YINGHUO-PLUGIN.md)。这项决策没有放宽云端发布、账号连接或付费制作的授权边界。

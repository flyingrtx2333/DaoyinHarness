# ADR-0014：云端 PostgreSQL 持久化

- 日期：2026-09-06
- 状态：接受，已部署切换；见 [发布记录](../../deployment/RELEASE-20260906-WS-POSTGRES.md)

## 背景

云端试运行入口此前使用单实例 SQLite。它适合隔离测试和最初的单机服务，但不适合作为云端的长期共享存储：运行实例、数据库备份和将来的多进程扩展不能依赖一个主机上的文件锁。

本地运行形态不变：本地会话事实仍是追加式 JSONL，SQLite 仍是本地可重建索引和物化状态。本决策只替换 `server-cloud` 的云端存储。

## 决策

1. 云端 `main.ts` 使用 `DAOYIN_CLOUD_POSTGRES_URL` 连接 PostgreSQL，并在启动前仅校验已存在的表结构。
2. `postgres-migrate` 是唯一会创建/补齐云端表的入口；正常服务启动绝不自动执行 DDL。
3. PostgreSQL 保存会话、Run、不可变事件、压缩摘要、版本化长期记忆、共享授权与审计记录。事件写入和 Run 物化状态在同一事务提交；终态之后拒绝迟到写入。
4. 运行租约由数据库行和事务内复核实现。旧实例续约失败后停止接收新工作；其后续状态写入会被拒绝。租约不自动重放模型或外部操作。
5. `sqlite-to-postgres` 只在旧服务完全停止、活动任务为零且已备份 SQLite 文件后显式执行。目标业务表必须为空，冲突直接回滚；核对每张表数量，不静默跳过记录。它不复制旧运行租约，也不由服务启动自动触发。

## 已验证的目标服务器条件

2026-09-06 已在 `42.194.159.81` 本机核实：宝塔 PostgreSQL 位于 `/www/server/pgsql`，数据库端口为 `5432`，当前 `listen_addresses=localhost`，仅监听 `127.0.0.1` 与 `::1`。目标数据库和可登录角色均已存在。

这不是密码或数据库不存在的问题。运行 Harness 的宿主进程若也部署在该服务器，应连接回环地址；不能使用该服务器的公网 IP。若 Harness 位于另一台机器或 Docker 容器，必须先通过受控网络、`pg_hba.conf` 与防火墙规则授予该部署来源访问权，再切换服务。

## 后果

- 云端部署必须把 PostgreSQL 连接串从受保护的环境变量或密钥管理器注入，不能写入仓库、前端、日志或会话记录。
- 数据库应只允许 Harness 服务所在网络访问，并使用私网连接或 TLS；不能以公开、无访问限制的数据库端口代替服务端身份和租约校验。
- 2026-09-06 已在用户授权下完成备份、显式迁移及导入；12 个会话、26 个 Run、1,049 条事件逐行校验一致。切换后的新消息只写 PostgreSQL；禁止直接回退旧 SQLite 丢弃新事实。

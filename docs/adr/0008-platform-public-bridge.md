# ADR-0008：主平台治理与官网只读执行桥

- 日期：2026-09-05
- 状态：接受；实现与验证结果见 `docs/UNIFIED-AGENT.md`

## 决策

Harness 是本地与云端共用的通用 Agent 内核。主平台拥有账号、空间、应用安装、授权、费用归属和业务资源；Python backend 不新增通用推理循环。官网是首个只读接入对象，Story、Youji、Builder 继续拥有自己的业务状态与长任务。

主平台签发随机、短期、可撤销的访客授权，数据库仅保存令牌摘要。访客身份与配置明确的付款成员分别记录；授权只有 `agent.use` 和 `company.knowledge.read`，不会继承付款成员权限。每次请求、模型和检索调用重新检查授权、配置版本及付款成员有效性。

云端使用固定平台地址和专用服务凭据访问内省、授权复查、模型及检索接口。服务凭据仅允许访问官网桥；每次业务调用还必须携带有效授权编号。禁止重定向、自动重试、模型指定目标地址或任意身份。模型返回工具调用后仍由共享内核和注册表执行授权检查。

主平台以 MySQL 事务锁定授权记录，原子登记操作与次数额度。同一授权、Run、操作编号和正文只执行一次；重复完成请求返回原结果，正文冲突或未知结果拒绝重新收费。次数上限是防滥用门禁，不是金额预算或账务结算。错误、进程中断后的未完成操作需核对，不自动重跑。

官网新 API 通过 HttpOnly SameSite Cookie、严格 Origin 与 CSRF 校验代理会话、Run、回放及取消。访客令牌不出现在 JSON、浏览器存储或 transcript。旧官网 chat 保留，由后续界面接入和真实验收决定切换；禁止同一消息双跑。

## 持久化边界

平台新增独立授权、操作、额度表，显式迁移，不在应用启动时修改生产结构。Harness SQLite 仍仅支持单实例；本地 JSONL 仍是本地 canonical transcript。生产多 Worker 调度、跨业务记忆、付费业务写操作和统一金额冻结不属于此只读桥。

## 验证

Windows 运行 Harness 类型检查、lint、测试和构建；Windows Docker Compose 运行 backend 测试，隔离 MySQL 验证授权/操作的并发与持久幂等。模拟模型和检索的集成测试不能作为真实模型、真实官网或生产部署证据。

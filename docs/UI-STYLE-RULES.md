# 全站 UI 样式规则

本规则适用于 Harness 的云端和本地页面、会话、插件、文件面板、设置及弹窗。单页改版（包括使用 concept-to-ui）必须延续全站字体、字号层级、padding、gap、控件尺寸、圆角、颜色和交互状态，不能让一个页面成为另一套视觉风格。

## 唯一参数来源

公共参数在 [design-tokens.css](../packages/ui/src/design-tokens.css)。本地样式通过 `styles.css` 引入，云端样式通过 `cloud/main.tsx` 引入。新增页面必须复用这些参数；通用布局和控件优先复用现有组件及样式，不复制一套后自行调整。

| 用途 | 桌面基准 |
| --- | --- |
| 正文 | 14px，行高 1.6 |
| 控件、导航 | 13px |
| 辅助说明、标签 | 12px |
| 卡片及区块标题 | 16px |
| 页面标题 / 欢迎标题 | 20px / 28px |
| 标准间距 | 4 / 8 / 12 / 16 / 20 / 24px |
| 页面 padding | 20px，窄屏 12px |
| 卡片 padding / 栅格 gap | 16px / 16px |
| 控件高度 | 桌面 36px，窄屏及触控主要操作至少 44px |
| 圆角 | 控件 8px，卡片 12px，面板 16px |
| 顶栏 / 侧栏 | 52px / 240px |
| 会话阅读区 / 插件目录最大宽度 | 820px / 1120px |

大屏增加可用内容空间，不按 viewport 放大整站字号、padding 或按钮。禁止用根字号 `vw`、整页 `zoom` 或 `transform: scale()` 调整密度。触控输入可使用 16px 字号避免移动浏览器自动放大，这是输入场景的共享例外，不能扩展成整页放大。图标和装饰可以有独立尺寸，但不能代替正文层级。

## 修改与 concept-to-ui 流程

1. 改前同时检查目标页面、会话页及一个相邻页面或弹层的实际样式，先定位公共参数与组件。
2. 概念生成提示词必须写入本规范的字体、密度、间距、圆角、配色和 [品牌规范](HARNESS-BRANDING.md)。概念方案可改变内容组织和功能重点，不能擅自更换全站视觉语言。
3. 选定概念后，将视觉值映射到现有公共参数。概念图里的夸张留白或字号不能直接作为独立页面的实现值。整站设计系统的变更须有用户明确要求，并同步修改所有受影响页面及本文。
4. 从原有定义处调整，不在文件尾不断追加同选择器覆盖，不新建页面私有的同用途 token；共享参数不得在单页重新定义。已有历史尺寸逐步迁移，不能作为新增不一致样式的理由。
5. 不通过删掉功能、隐藏重要状态、压小可读文字或缩小触控目标解决拥挤。无实际信息的重复副标题应移除。

## 验收

在 Windows 浏览器中检查会话空态、已有回答、插件目录、插件选择器及本地工作台；至少覆盖 1280×720、桌面大屏、390px 和 320px 窄屏。检查跨页面字号与控件一致、内容无水平溢出、卡片内容完整、输入区可见、键盘焦点与滚动正常。

相关入口为 [云端验收](../scripts/verify-cloud-modern-ui.mjs) 和 [本地验收](../scripts/verify-workbench-polish.mjs)。必须区分本地浏览器与模拟接口证据、真实模型调用及生产部署；本地通过不能写成已上线。

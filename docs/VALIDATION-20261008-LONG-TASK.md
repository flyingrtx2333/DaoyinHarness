## Limits of this evidence

The model identity, provider token counts, settlement and monetary cost are **unknown**. Model-attempt counts use persisted AgentEngine `model.requested` events; routing requests and total provider requests are not represented by those counts. Reported durations come from persisted events and inclusive server diagnostics, not provider token latency. Neither successful semantic-compaction requests nor use of a `semantic-trajectory-v3` derived context were observed in this snapshot. The successful multi-turn report explicitly records `summaryModelAttempts=0` and `not-verified-no-observed-compaction`. Continuation with a persisted plan does not validate semantic compression, memory withdrawal or overflow recovery.

The real public BFF accepts only UUID `requestId` and `message` for a run; an optional `maxModelCalls` field was actually rejected with HTTP 400 `INPUT_INVALID` before admission. Controlled drivers reserve the ordinary server allowance of 12 model calls and 24 tools per run and collect persisted accounting. Known infrastructure/auth failures stop further paid work; uncertain POST results are resolved read-only rather than resubmitted. These are driver safeguards, not a claim that every failure mode has passed a real task.

No fake-model, mock/stub API/browser, transcript replay or legacy Vitest suite was run. Necessary type/lint/build and diff checks are static/packaging evidence only. The development checks used an independent macOS arm64 checkout and Node.js 22.23.2; the revision-stamped production artifacts were built in the independent Linux server checkout. Neither environment is Windows/WSL shared-checkout acceptance, and no Windows acceptance is claimed.

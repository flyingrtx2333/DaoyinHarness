# 长期记忆：作用域、版本与引用

2026-09-06。本轮为 Harness 源码改造：持久化、管理 API 和共享 AgentEngine 读取链已接线。Windows 专项测试、相关包类型检查与服务端构建已通过；全仓构建也通过。Git 提交和部署尚未进行。全仓 lint 与测试仍分别受生成的 Saishi 发布产物、以及本地服务崩溃恢复断言影响，均不属于本记忆模块。没有修改 DaoyinTechnology、签发新平台权限、迁移本地历史或调用真实模型。当前线上是否运行此代码不能由本地文件存在推断。

## 当前实现与范围

已有本地端使用 `JsonlMemoryStore` 和 `memory_search / memory_remember / memory_update / memory_forget`，不是只有对话压缩。本轮保留这些本地数据和行为，新增云端的版本化长期记忆，不自动把本地 account 记忆上传到云端或映射成企业资料。

| 对象 | 保存内容 | 本轮处理 |
| --- | --- | --- |
| 会话事件 | 用户问题、工具执行、回答和终态 | 保留原 append-only 记录 |
| 压缩摘要 | 老会话的派生上下文 | 无长期记忆读取器时保持原流程；配置记忆读取器后暂不复用没有依赖版本的旧摘要 |
| 公开知识库 | 公司公开资料、文档和来源 | 原业务检索不变，不当作私人记忆 |
| 云端长期记忆 | 已确认的偏好、事实、目标、决策或备注 | SQL 记录、版本、候选确认、过期和撤销 |
| 共享授权 | 某条有效版本允许在哪个应用使用 | 逐条、逐目标安装实例授权，最长 30 天，随时可撤销 |
| 引用回执 | 哪轮哪步准备了哪些记忆版本及原因 | 只存 ID/版本/授权/原因，不再复制正文 |

实现位于 `packages/server-cloud/src/memory-policy.ts`、`memory-repository.ts`、`memory-runtime.ts`、`memory-routes.ts`。共享引擎接口位于 `packages/agent-core/src/memory-context.ts`。

## 写入与更正

```text
用户管理请求 + 可信执行身份
  → 严格字段、作用域、来源检查
  → requestId 幂等 + 稳定 key 去重
  → pending 候选（不参与召回）
  → 用户通过管理 API 确认 revision
  → active 可召回
```

`scope / key / kind / content` 是记忆属性；用户、企业和所属应用从已认证身份派生，不接受请求正文另填用户或租户。会话来源必须对应本身份可访问的实际 `turn.started` 用户消息，不能填写一个虚构 ID 就获得来源可信性。来源关联不能证明摘要语义一定正确，所以仍需人工确认。

候选更正以 `replaces: { id, revision }` 关联旧版本。旧版本在确认前继续生效；确认在事务中验证旧版本，随后使旧记录 superseded、新记录 active，并撤销旧版本共享。两个候选并发确认不能覆盖彼此。拒绝候选只清空该候选正文，不删除旧有效记录。

同一请求和内容重试返回原记录；同一请求不同内容返回冲突。使用同一稳定 key 保存不同内容，必须按更正流程处理；不同 key 或不同应用下语义相同/矛盾的文本尚无模型级自动去重或冲突裁决。

忘记会将此仓储相同 key 版本链标记 forgotten，清空可查询记录的正文和关键词，撤销授权。原请求重试不会恢复内容。用户使用新 requestId 重新提交，可以生成新的 pending 候选；只有再次确认才生效，旧共享不恢复。此操作不是 SQLite WAL、空闲页、历史回答、供应商日志、旧本地 JSONL 或备份的物理擦除；不要宣称全盘遗忘。

**本轮没有自动从聊天抽取并激活长期记忆，也未注册模型可用的确认、共享、删除工具。** 目前候选通过管理 API 创建，用户确认后自动参与读取。后续“记住这句话”的聊天入口应只生成待审候选或使用真实用户确认票据，不能让模型自填 confirm 获取权限。

## 同账号插件访问规则与当前实现边界

按 [ADR-0012](adr/0012-first-party-account-access.md)，所有业务插件须自动继承同账号在当前空间内已有的完整权限；跨应用读取已有权限的记忆不要求逐条、逐目标插件授权。下面的共享表、接口和示例记录当前实现，尚需调整为该自动访问规则，不能作为后续产品继续要求手动授权的依据。记录归属、版本、更正、候选确认与忘记仍是独立的内容生命周期。

## 当前共享实现（待按新规则调整）

| 作用域 | 默认可用范围 | 共享边界 |
| --- | --- | --- |
| application | 当前用户、当前空间、当前应用安装实例 | 不允许直接跨应用共享 |
| personal | 当前个人空间的本人；记录仍保留来源应用 | 用户可逐条授权本人在同一空间的目标应用 |
| organization | 同一企业空间中具有企业记忆权限的成员 | 有管理权限的成员可授权同一企业的目标应用 |
| public | 不开放上述私人长期记忆 | 官网匿名访客不能借官方付款身份访问 |

不同用户、不同企业，以及同一人的个人/企业身份不会因账号相同而混用记忆。企业应用私有记录仍以用户为所有者，只有明确的 organization 范围才是企业共享记录；普通企业读者不能看到其他人的待审候选。部门级/资源级 ACL 还未实现，不能把机密人事档案放进普通企业共享记忆。

主平台必须实际签发 `memory.read`、`memory.write`、`memory.share`；企业记录另需 `memory.organization.read / memory.organization.write`。字符串类型定义不是授权实现。所有管理请求继续使用云端的真实认证与授权复查，缺失权限即拒绝。

共享 API 还要求 `CloudServerOptions.authorizeMemoryShare`。该可信回调必须检查目标应用已开通且属于当前个人/企业空间；缺失时返回 503，拒绝时返回 403。共享授权绑定记忆版本、目标应用实例和期限，不随更正自动扩散。权限和目标安装状态的实时复查仍由主平台认证适配器负责，本轮没有假造该接口或放宽业务工具白名单。

## 读取、引用与撤销

```text
每个推理步骤
  → 复查当前执行授权
  → 按用户 / 企业空间 / 应用 / 有效共享授权筛选 SQL 记录
  → 排除未确认、过期、撤销、更正掉的版本
  → 中文词对 + 英文词项排序，最多 6 条，记录正文合计不超过 8,000 字符
  → 检查旧回合的记忆依赖和原始来源
  → 从模型视图隔离失效记忆影响的旧回合
  → 保存不带正文的引用回执
  → 注入 UNTRUSTED_CONFIRMED_MEMORIES
  → 模型调用前后、工具发出前再检查引用
```

本轮检索是确定性关键词检索，不是向量检索、语义检索或额外一套 Agent。仅共享权限不会让无关记忆每次出现；用户问题与内容/关键词需要相关。不会自动调用 embedding 或额外收费模型。超长查询仅取前 500 字符，完整当前用户目标仍由引擎保留。

例：本人在短剧中确认“视频偏好竖屏”，未授权前文旅应用读不到；授权该版本到本人文旅安装实例后，相关问题可召回。撤销后新步骤读不到该条；正在使用该版本的模型回复不再用于回答或触发新工具。已经发出的供应商调用或外部操作不能被回溯撤销，也不保证不产生费用。

引用包括 `memory id + revision + share id`。从历史回答继承的依赖继续记录到当前回合，因此撤销不能仅靠改一条记录来绕过旧回答的影响。原始来源消息即使没有命中本轮检索，也参与依赖检查。引用回执表示“准备进入本轮上下文”，不是证明模型逐条采纳，更不是实际采用率指标。

为防止旧摘要残留，启用此读取器的私有会话目前不复用缺少记忆依赖图的压缩摘要，而从有效事件重建并由总预算裁剪历史。这是保守方案，可能减少旧对话细节；下一阶段可增加依赖感知摘要缓存，失效时重建，不能直接复用旧文本。公网问答及未挂此读取器的本地流程仍使用原压缩方式。

## 管理 API

以下是 Harness 云端接口，不是已完成的官网 BFF 或管理界面。前端接入必须沿用安全的认证代理，不能把内部服务凭据放入浏览器。

| 方法与路径 | 操作 |
| --- | --- |
| GET `/api/v1/cloud/memories/capabilities` | 仅返回当前已认证身份可用的记忆能力、作用域和共享目标核验状态，不返回记忆正文 |
| GET `/api/v1/cloud/memories?offset=0` | 当前应用可管理/查看记录，50 条分页 |
| POST `/api/v1/cloud/memories` | 提交严格的候选和可选会话来源 |
| POST `/api/v1/cloud/memories/search` | 查询当前有效且可访问的记忆 |
| GET `/api/v1/cloud/memories/:id` | 读取可访问的有效记录 |
| POST `/api/v1/cloud/memories/:id/confirm` | 按 revision 确认候选 |
| POST `/api/v1/cloud/memories/:id/reject` | 按 revision 拒绝候选 |
| POST `/api/v1/cloud/memories/:id/forget` | 按 revision 忘记版本链 |
| GET / POST `/api/v1/cloud/memories/:id/shares` | 查看或创建共享授权 |
| POST `/api/v1/cloud/memories/shares/:id/revoke` | 撤销共享 |
| GET `/api/v1/cloud/memories/:id/audit?offset=0` | 管理者查看不含正文的生命周期审计记录 |
| GET `/api/v1/cloud/runs/:runId/memories` | 查看当前身份拥有的 Run 引用回执 |

新增 `durable_memories`、`memory_requests`、`memory_shares`、`memory_audit`、`memory_references`，由当前单实例 SQLite 仓储初始化，写入复用运行租约门禁。本轮没有在生产或用户历史库上执行初始化。不是多实例 MySQL 统一记忆服务；当前容量与依赖上限按试运行设计，达到上限明确拒绝，不静默漏掉撤销检查。

## 验证与后续缺口

新增四个测试文件：`memory-policy.test.ts`、`memory-repository.test.ts`、`memory-routes.test.ts`、`agent-core/src/memory-context.test.ts`。覆盖纯策略、临时真实 SQLite、真实 Fastify/共享 AgentEngine 与模拟认证/模型组合；没有真实供应商调用。管理 API 现提供能力声明与不含正文的审计查询；候选仅能由其管理者读取。Run 引用回执也要求当前身份仍持有 `memory.read`，权限撤销后不会泄露引用标识。

官网 BFF 和管理界面仍需主平台把这些同源 API 安全映射给已认证用户；Harness 不会把执行服务的 Bearer 凭据交给浏览器，也不会假装已经拥有主平台的跨应用安装核验。发布前仍需完成仓库级验证和独立上线记录。

接通真实用户前需要：主平台记忆权限与目标应用检查、同源管理入口和确认界面、真实隔离联调。之后再做聊天候选提取、语义召回评估、资源/部门 ACL、依赖感知摘要、细粒度历史遗忘策略及多实例持久化。不能仅因 API 和测试文件存在就宣称 C 端线上记忆已经互通。
